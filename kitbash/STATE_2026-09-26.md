## 4. WHAT HAPPENED THIS SESSION — honest record

**Delivered:** `kitbash/muster.ps1` + `kitbash/README.txt`, committed `6b7bae6`,
pushed to `claude/vibrant-knuth-e9ez4u`. The scan ran and produced §1.

**Two defects, both mine:**

1. **The chat-pasted script and the committed file diverged.** The paste used
   `$bytes`, accumulated once outside the loop; the file uses `$assetMB`, reset per
   asset (line 217, verified). With 5.95 GB of models the cumulative version trips
   the 512 MB sidecar cap almost immediately, so **the 479 models it copied into
   `KITBASH_MUSTER\KITBASH_RAW` mostly lack their `.mtl` and textures.** That folder
   is throwaway — it holds only copies, every original untouched.
2. **The safety gate didn't hold on an interactive paste.** `return` inside
   `if (-not $Gather)` halts a script, not a console paste. It printed "NOTHING WAS
   COPIED" and the gather block ran anyway. Handing him paste-text of a
   file-oriented script was the wrong call. Nothing was lost — copy only, no
   `Move-Item`, no deletes, confirmed in his transcript.

**Two fixes still owed to `muster.ps1`:**
- Default `-Roots` to the §1.2 folders instead of all of `%USERPROFILE%` — the full
  walk cost 632,210 files, most of it AppData.
- Skip reparse points. `AppData\Local\Application Data` is a self-referential
  junction; whether PS 5.1's `-Recurse` followed it here is **unverified**, but the
  count is consistent with it and the script has no guard either way.
